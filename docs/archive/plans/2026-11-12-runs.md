# Runs Implementation Plan

> **Archived 2026-11-13.** Implementation plan, carried out. Kept for the task breakdown and the gates it defined; the code is the record now.
> Current behaviour: [`README.md`](../../../README.md) · agent rules: [`AGENTS.md`](../../../AGENTS.md).

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the dashboard own a repeatable **run** — a fresh directory, diary, overlay, save wipe, game restart, body reset and brain loop — while the Monado/Weston/Steam stack stays up between runs.

**Architecture:** A new `clank/run.py` `RunManager` owns the run state machine, its directory and the brain child process, and calls two new `SessionManager` methods (`wipe_game_saves`, `restart_game`). The dashboard gains `/api/run/*`, puts the run in `/api/state`, and reads the current run's diary instead of the global one. The body is reset through the existing `BodyPreview` sidecar, not through the session manager.

**Tech Stack:** Python 3 stdlib only (`clank/`), `http.server`, `subprocess`, `unittest`; vanilla HTML/CSS/JS for the dashboard; TOML config.

**Spec:** `docs/superpowers/specs/2026-11-12-runs-design.md`

## Global Constraints

- `clank/` is **standard-library only**. No numpy, torch, requests, pytest. Tests use `unittest`.
- `config.toml` is git-ignored and machine-specific. New keys go in `config.example.toml`, `DEFAULTS`, the section dataclass, and `_validate`. Unknown `CLANK_*` env overrides must still be rejected.
- No new `CLANK_*` environment variables. The only ones this plan introduces are `CLANK_BRAIN_LOG` (already read by `brainlog.default_path()`) and `CLANK_AUTO_STATE` (read by `spike/wbc_game/auto.py`, never by `clank/`).
- Do not hardcode `/nix/store` paths, the compatdata id, or the game's save paths in code. The prefix comes from `cfg.launch.proton_app_id`; the save directories come from `cfg.paths.game_save_dirs`.
- Commit messages are lowercase prose, no conventional-commit prefixes (the repo's log style): `git log --oneline -5`.
- Every task ends green on: `mkdir -p "${XDG_RUNTIME_DIR:-/tmp/clank-xdg}" && XDG_RUNTIME_DIR="${XDG_RUNTIME_DIR:-/tmp/clank-xdg}" python3 -m unittest discover -s tests -t .`
- Before any `nix build`, `git add` new files: flakes only see tracked files.
- `RunManager` never holds `SessionManager._lock` while waiting on a child process or an HTTP probe.

## Review Focus

- **Shut down during the `game` phase.** The stack must not shut Steam down until the run is idle, and the run must never spawn a brain child afterwards — an orphan `auto.py` writing into a deleted session directory is the worst outcome here.
- **Start run while the model server is loading.** A 2B Q8_0 load takes tens of seconds; the run must wait and then proceed, not fail. This is the normal case after a reboot.
- **A save directory that escapes the Proton prefix** — absolute, containing `..`, or a symlink pointing out. It must be refused, and nothing outside the prefix may ever be deleted.
- **`/api/brain/messages?run=` with separators or `..`.** Must be a 404, never a read outside `sessions/<session>/runs/`.
- **Dashboard restarted with run directories on disk.** The Brain panel must show the last run's rows instead of blank, and Start run must work again with no in-memory state.
- **The brain child exiting immediately** (bad interpreter, missing script, no model). The run must end `failed` with an exit code and a readable tail in `brain.log`, and the stack must keep running.

  class RunState(StrEnum): IDLE, CHECKING, PREPARING, GAME, BODY, BRAIN, RUNNING, STOPPING, FAILED

      def brain_argv(self) -> list[str]
